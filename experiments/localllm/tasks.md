# teaspoon-ide 実タスク計測手順

`results.md` §3 の実施手順。

- フィクスチャ原本: `bench/fixture/`（calc/cart/main + pytest、**直接開かない**）
- 投入プロンプト: `bench/prompts/<テストID>.txt`（テストIDと1対1、内容をそのまま貼る）
- 実行用プロジェクト: `bench/runs/<モデル>/<テストID>/` に fixture をコピー済み（使い捨て）

## 準備（モデルごと）

1. Settings → LLM Provider = Ollama、Model = 計測対象、CPU Threads = 4、Context Size = **8192**（要ビルド版 — 未指定だと Ollama 既定 4096 で、gpt-oss は応答途中に枯渇して空応答になる実績あり）
2. Thinking 設定:
   - qwen3.5 系 / gemma4 系: `Off`（gemma4 は `Model default` でも可）
   - gpt-oss: `Low`（`Off` は自動で low に降格するが、明示しておく）
3. `bench/runs/<モデル>/<テストID>` を Open Project
4. 新規チャットを開き、`bench/prompts/<テストID>.txt` の内容をそのまま貼り付けて送信
5. 同じテストをやり直す場合: `runs/<モデル>/<テストID>` を削除して `fixture/` を再コピーし、新規チャットで（前回の編集・履歴が残っていると公平でない）

## 記録すること

- 各ターンでモデルが出したコマンド列（チャットに残る `// XXX:` 行と実行結果）
- ターン数（結果フィードバック1往復 = 1ステップ）
- フォーマット崩れの有無・種類（`//` 抜け、フェンス囲み、終端忘れ、JSON出力など）と、パーサーが救済できたか
- 最終ファイル内容の正しさ（diff で確認）
- 体感待ち時間

## T0: 新規ファイル作成（1ステップ・形式遵守の基礎）

プロンプト: `prompts/T0.txt`

- 期待: `// WRITE_FILE: hello.py` ブロックが正しく開閉され、承認後にファイルが作られる
- 落ちどころ: コードフェンスで囲んで本文が ``` で汚染される、`END_WRITE_FILE` 忘れ、コードを普通に markdown で返す（コマンドを出さない）

## T1: 探索→回答（2-3ステップ）

プロンプト: `prompts/T1.txt`

- 正解: `cart.py` の `Cart.total()`（`discount` 経由）
- 期待: `// GREP:` / `// READ_FILE:` / `// LIST_FILES:` のいずれかを出して内容を見てから回答
- 落ちどころ: コンテキストに中身がないのに推測で答える、コマンドを出さず一般論を述べる

## T2: 部分編集（3-4ステップ・EDIT_FILE が本番）

プロンプト: `prompts/T2.txt`

- 期待: READ_FILE（または既知を利用）→ `// EDIT_FILE:` の `<<<<<<< SEARCH` が実ファイルと完全一致 → `>>>>>>> REPLACE`
- 確認: `git diff` or 目視で `mul` 以外が無変更、`scale` 引数が正しい
- 落ちどころ: SEARCH テキストの空白・docstring 不一致、ファイル全体を WRITE_FILE で書き換える（許容だが減点）、コメントアウト混入

## T3: バグ修正 + 検証（4-5ステップ・総合）

プロンプト: `prompts/T3.txt`

- 期待: RUN_COMMAND（承認が出るので承認する）→ 失敗内容を読む → READ_FILE calc.py → EDIT_FILE で `price * rate` → `price * (1 - rate)` に修正 → RUN_COMMAND 再実行 → 全パス報告
- 合格ライン: **5ステップ以内に完走**（design.md 判定基準）
- 落ちどころ: テスト側を書き換える（誤修正）、修正後に再実行せず「直ったはず」と述べる、RUN_COMMAND を出さず手順説明だけする

## 採点（各項目 ○/△/× + メモ）

| 観点 | ○ | △ | × |
|---|---|---|---|
| フォーマット遵守 | 全コマンド正しい形式 | 崩れたがパーサー救済で動いた | 実行不能な形式・ハルシネーションコマンド |
| ループ完走 | 想定ステップ内で完走 | 余計な往復があったが完走 | 途中で破綻・放棄 |
| 編集の正しさ | diff が意図通り | 一部正しい | 誤編集・無関係な変更 |

実施メモ:

- RUN_COMMAND の承認操作は計測時間に含めない（人間の応答待ちはモデル性能と無関係）
